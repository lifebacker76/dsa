## Overview

Take a trained ML model from any previous project and deploy it as a **production-ready REST API**. You'll build a FastAPI app, containerize it with Docker, and (optionally) deploy it to the cloud. This is the bridge between "I built a model in a notebook" and "my model is serving real predictions."

**Goal:** Serve ML predictions through a REST API that anyone can call.

---

## Steps

### Step 1: Train and Save a Model
- Use any model from a previous project (house prices, sentiment, etc.)
- Save with `joblib` (sklearn) or `torch.save()` (PyTorch)
- Verify you can load and predict with the saved model
- Save any preprocessing artifacts (scaler, tokenizer, etc.)

### Step 2: Build FastAPI App
- Create endpoints:
  - `GET /` — Welcome message
  - `GET /health` — Health check (returns `{"status": "healthy"}`)
  - `POST /predict` — Accept features, return prediction
- Add Pydantic models for request/response validation
- Load model once at startup (not per request!)
- Handle errors gracefully (invalid input, model not found)

### Step 3: Add Health Check Endpoint
- `GET /health` returns:
  ```json
  {
    "status": "healthy",
    "model_loaded": true,
    "model_version": "1.0.0",
    "timestamp": "2024-01-15T10:30:00Z"
  }
  ```
- This is standard practice for production APIs

### Step 4: Write Dockerfile
- Base image: `python:3.11-slim`
- Install dependencies from `requirements.txt`
- Copy app code
- Expose port 8000
- Run with `uvicorn`

### Step 5: Build and Run Docker Container
```bash
# Build the image
docker build -t ml-api .

# Run the container
docker run -p 8000:8000 ml-api

# API is now at http://localhost:8000
```

### Step 6: Test with curl/requests
```bash
# Health check
curl http://localhost:8000/health

# Make a prediction
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"feature_1": 1.5, "feature_2": 3.0, "feature_3": 2.1}'
```

### Step 7: (Optional) Deploy to Cloud
- **Railway** — Easiest, free tier, auto-deploys from GitHub
- **Render** — Free tier, good for demos
- **AWS EC2 / ECS** — Production-grade, more setup
- **Google Cloud Run** — Serverless, pay-per-request
